## 2. P0 留下的关键事实（别重复试错）

1. **`MaidTraitV2` 只能放 `platform/impl`**（继承 Citizens `Trait`，环2 禁止 import Citizens）。
   - trait 名 `tlm`；DataKey 键 `maid`；`run()` 永不被调，行为由插件 tick 驱动。
   - spawn 链已经在 `CitizensEntityPlatform#spawn` 内 `getOrAddTrait(MaidTraitV2.class)`，P1 不要再注册第二份。
2. **玩家型 NPC 没有自动走路动画**；`animate` 的 LOOP 补播由适配器按 per-npc 计时表负责，P1 不要在业务层重复补播。
3. **骨物品上下文**：`MaidModelPlatform#setBoneItem` 内部已自动套 `THIRDPERSON_RIGHTHAND`；不要为每件物品写死握点。
4. **CE 自定义音效**：`sounds.yml` 的 `name` 必须写全限定名（`touhoulittlemaid:maid_hurt`），否则客户端解析成 `minecraft:` 静音；改包后必须 `ce reload all`。
5. **PDC/CE 键前缀**：R2 裁决后一律 `touhoulittlemaid:`，禁止 `catmaid:`（含 CE 物品 id）。
6. **v1 兼容已整体废止**（R2-5）：不要写 `MigrationFromV1`、`/tlm admin migrate-v1`、v1 铃铛识别/转换。
7. **`softdepend` 是服主裁决**（R2-3）：不要改回 `depend`；onEnable 的 `checkDependencies()` 必须保留。
8. **CE 测试包**（`plugins/CraftEngine/resources/tlmtest/`）是测试服资产，不进仓库；`namespace: touhoulittlemaid`。

## 3. P1 范围与必须落地的文件

按 `blueprint.md` Phase 1（R2 后版本）：

| 文件 | 要点 |
|---|---|
| `core/domain/**` | `Maid` / `MaidManager` / `MaidStats` / `FavorabilityManager` / state / schedule；`FavorTier` 已存在，`MaidInventory` 在本阶段补物品存储 |
| `data/Database.java` | SQLite 建表；连接生命周期照 v1 |
| `data/MaidRepository.java` | maids 全字段 + maid_items 全量重写 + maid_stats + player_prefs；**单线程 executor**，onDisable 同步 flush |
| `util/MaidItems.java` | 魂符/胶片物品工厂与识别；先走 CE `touhoulittlemaid:talisman`，CE 缺失回落原版材质 + PDC 并告警 |
| `listener/TalismanListener.java` | 魂符三态，逻辑照 v1（api-facts 25.3/25.4） |
| `command/tlmCommand.java`（正式命令树） | `/tlm` 帮助 + `soul` + `admin summon/remove/list/reload` + `release` + `admin quota`；**整体替换 `/tlm spike`，不做别名** |

### 关键设计约束

- **环1 禁 Bukkit**：`core/domain/MaidInventory` 不能 import `org.bukkit.inventory.ItemStack`。
  P1 需要先定“物品在域内的表示”（建议 `byte[]`（`ItemStack#serializeAsBytes`）或平台无关快照），
  在环2 的 `data/`/`util/` 层转换。不要为了省事让 core 依赖 Bukkit——`check_rings.py` 会挂。
- **`applyEquipment` 空实现要补**：`CitizensEntityPlatform#applyEquipment` 目前是 P0 占位；
  P1 把 `MaidInventory` 的 0-5 槽写回实体 equipment（主手/副手/头/胸/腿/靴）。
- **`FavorabilityManager` 不 import Bukkit**：按 blueprint 注入 `TierApplier` 函数接口，由 app/manager 层绑定 `entityPlatform.applyAttributes(npcId, tier, false)`。
- **quota 语义**：召唤成功 +1；死亡/收纳/送走 **不减**；`/tlm admin quota <玩家> <数值>` 供管理员修正。
- **随机模型**：从服务端已加载模型清单均匀随机，失败回退 `config.models` 第一个（默认 `hakurei_reimu`）。
- **玩家可见文案**：P1 开始出现 `/tlm soul`、拒绝/提示消息，**必须走 `messages.yml`（MiniMessage）**，禁止在代码硬编码中文。
- **数据库路径**：`plugins/TouhouLittleMaid/tlm.db`；`sqlite-jdbc` 是唯一 shade 依赖，**禁止 relocate**（api-facts 26.3）。

## 4. P1 验收清单（blueprint Phase 1）

- [ ] `/tlm soul` 领魂符 → 右键顶面召唤 → 手中变空魂符（三态不变）；重启后女仆/好感/任务/背包全恢复
- [ ] 魂符收纳 → 重启 → 释放全链保留（v1 行为回归）
- [ ] quota：召唤满 2 只后第三次拒绝；`/tlm release` 不释放 quota；`/tlm admin quota` 可修正

建议自测顺序：domain → DB（建表/CRUD 单测或控制台）→ `MaidItems`（CE/回落两条路径）→ `TalismanListener` 三态 → 正式命令树 → 重启恢复 → quota。

## 5. 测试服操作手册（P0 已验证）

- 启动：`cd testserver` → `java '-Dterminal.jline=false' '-Xms1G' '-Xmx2G' -jar paper-26.2-135.jar nogui`（后台运行）
- 控制台命令：`python tools/rcon.py "<命令>"`（RCON `127.0.0.1:25575`，游戏端口 `25566`，offline mode）
- 当前测试服有 1 个 P0 探针 NPC（winefox，挂钻石剑）；P1 替换探针后可清理
- BetterModel 模型：`testserver/plugins/BetterModel/models/`；改模型后 `bettermodel reload`，必要时重建 NPC
- CE 资源包：改 `resources/tlmtest/` 后必须 `ce reload all`；测试资产不入仓库
- 已知非插件 ERROR：离线模式启动时 Paper 可能刷 `Failed to request yggdrasil public key` / 版本检查失败，属网络环境，不影响验收

## 6. 传递到后续阶段的风险（P1 先知道，不要求现在解决）

1. **V0-5**：玩家型 NPC 死亡会派发 `PlayerDeathEvent`，CE 的 `EntityDeathLootListener` 会 NPE。
   P1 若涉及死亡/收纳，必须避免走原版死亡（或拦截后自管状态），否则每次死亡刷 ERROR。
2. **V0-6**：Citizens 直接穿过关闭的门，不触发开门；P3 必须自己实现“临近开门→通过→关门”。
3. **FOX 第二骨架**：原版 `parallel1` 用血量 `<20%` 控制显隐，`sit/gomoku/picnic` 才转为坐垫；
   P4 必须补 `FOX scale` 规则，不能默认常显。
4. **模型组朝向**：`winefox` 的 `RightHandLocator` 旋转已固定 `[-90,0,180]`，配合自动 `THIRDPERSON_RIGHTHAND`；
   换模型/换手部骨时需重新验收握点。
